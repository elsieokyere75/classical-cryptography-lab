# Elliptic Curve Digital Signature Algorithm (ECDSA)

## 1. Introduction

The Elliptic Curve Digital Signature Algorithm (ECDSA) is a digital
signature algorithm based on elliptic-curve cryptography.

ECDSA allows a signer to create a digital signature using a private key.
A verifier can then verify the signature using the corresponding public
key without learning the private key.

ECDSA provides:

- message integrity
- authentication of the signer when the public key is properly authenticated
- evidence that the holder of the private key produced the signature

This implementation is educational and uses very small parameters.

---

## 2. Elliptic Curve

This project uses the educational curve:

y^2 ≡ x^3 + 2x + 2 (mod 17)

Therefore:

a = 2
b = 2
p = 17

The base point is:

G = (5, 1)

The order of G is:

n = 19

Therefore:

19G = O

where O represents the point at infinity.

The distinction between p and n is important.

p controls the finite field used for point coordinates, while n is the
order of the subgroup generated by G.

---

## 3. Private and Public Keys

Alice chooses the private key:

d = 7

The private key must remain secret.

Alice calculates her public key:

Q = dG

Therefore:

Q = 7G

For our curve:

Q = (0, 6)

Thus:

Private key:

d = 7

Public key:

Q = (0, 6)

---

## 4. Message Hash

ECDSA signs a representation derived from the message hash rather than
directly signing arbitrary message text.

For our educational example, we use:

z = 9

This represents a small, already-prepared message-hash value for the
hand calculation.

Real ECDSA systems use cryptographic hash functions and process the
result according to the requirements of the selected ECDSA parameters.

---

## 5. Nonce

ECDSA requires a per-signature secret value called the nonce:

k

For our example:

k = 3

The nonce must satisfy:

1 <= k < n

The nonce must be protected carefully.

Reusing the same nonce with the same private key for different messages,
or exposing the nonce, can reveal the private key.

---

## 6. Signature Generation

The ECDSA signature consists of two integers:

(r, s)

For our example:

d = 7
z = 9
k = 3
n = 19

First calculate:

R = kG

Therefore:

R = 3G

From our elliptic-curve calculations:

R = (10, 6)

Take the x-coordinate and reduce it modulo n:

r = 10 mod 19

Therefore:

r = 10

Next calculate:

s = k^(-1)(z + rd) mod n

The modular inverse of 3 modulo 19 is:

3^(-1) = 13 mod 19

because:

3 * 13 = 39

and:

39 mod 19 = 1

Therefore:

s = 13(9 + (10 * 7)) mod 19

s = 13(79) mod 19

s = 1027 mod 19

s = 1

The final signature is:

(r, s) = (10, 1)

---

## 7. Signature Verification

The verifier knows:

G = (5, 1)
Q = (0, 6)
n = 19
z = 9

and receives:

(r, s) = (10, 1)

First calculate:

w = s^(-1) mod n

Since:

s = 1

we obtain:

w = 1

Next calculate:

u1 = zw mod n

u1 = 9

and:

u2 = rw mod n

u2 = 10

The verifier then calculates:

X = u1G + u2Q

Therefore:

X = 9G + 10Q

For this example, the resulting point has x-coordinate:

x_X = 10

Verification checks:

x_X mod n == r

Therefore:

10 == 10

The signature is valid.

---

## 8. Why Verification Works

During signing:

s = k^(-1)(z + rd) mod n

During verification:

w = s^(-1) mod n

The verifier computes:

X = u1G + u2Q

where:

u1 = zw

and:

u2 = rw

Since:

Q = dG

we obtain:

X = zwG + rwdG

Factor out wG:

X = w(z + rd)G

Since:

w = s^(-1)

we have:

X = s^(-1)(z + rd)G

From the signing equation:

s = k^(-1)(z + rd)

which implies:

z + rd = sk mod n

Therefore:

X = s^(-1)(sk)G

The s terms cancel modulo n:

X = kG

But during signature generation:

R = kG

Therefore:

X = R

This explains why the verifier obtains a point whose x-coordinate
corresponds to r.

---

## 9. Importance of the Nonce

The nonce k is security-critical.

Suppose the same nonce is reused to sign two different message hashes.

The signatures satisfy:

s1 = k^(-1)(z1 + rd) mod n

and:

s2 = k^(-1)(z2 + rd) mod n

Because both equations contain the same unknown nonce and private key,
an attacker can combine the equations to recover information that can
lead to the private key.

Therefore nonce reuse can completely destroy ECDSA security.

Production implementations must generate nonces securely or use an
appropriate deterministic nonce-generation procedure.

---

## 10. ECDSA and ECDH

ECDSA and ECDH both use elliptic-curve scalar multiplication, but they
serve different purposes.

ECDH provides key agreement:

A = aG
B = bG

Shared point:

S = abG

ECDSA provides digital signatures.

Private key:

d

Public key:

Q = dG

Signature:

(r, s)

Therefore, the same elliptic-curve mathematical foundation can support
different cryptographic protocols.

---

## 11. Security Assumption

ECDSA security depends on the difficulty of the elliptic-curve discrete
logarithm problem for appropriately selected cryptographic curves and
parameters.

Given:

G

and:

Q = dG

recovering d should be computationally infeasible for suitable
classical cryptographic parameters.

The tiny curve used in this project provides no real security.

---

## 12. Quantum Computing

ECDSA relies on elliptic-curve discrete-logarithm assumptions.

A sufficiently capable fault-tolerant quantum computer running Shor's
algorithm would be able to solve the underlying discrete logarithm
problem efficiently.

Therefore ECDSA is not considered post-quantum secure.

This is one motivation for studying post-quantum digital signature
schemes.

---

## 13. Security Limitations

This implementation is for education only.

It uses:

- a tiny elliptic curve
- a tiny subgroup order
- manually supplied nonce values
- simplified public-key validation
- simplified message-hash handling
- non-constant-time Python arithmetic
- no side-channel protections
- no standardized curve
- no production protocol protections

It must not be used to protect real data.
