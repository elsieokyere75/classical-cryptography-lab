# SHA-256

## 1. Introduction

SHA-256 (Secure Hash Algorithm 256-bit) is a cryptographic hash function that converts an input of arbitrary length into a fixed 256-bit hash value, also called a digest.

Unlike encryption, hashing is not designed to be reversed. SHA-256 does not use a secret key and there is no decryption operation.

SHA-256 is used for data integrity, digital signatures, certificate systems, and many other cryptographic applications.

---

## 2. Security Properties

A secure cryptographic hash function should provide several important properties.

### Preimage Resistance

Given a hash value:

h = H(m)

it should be computationally infeasible to determine a message `m` that produces that hash.

For SHA-256, generic preimage search requires approximately:

2^256 operations.

### Second-Preimage Resistance

Given a specific message `m1`, it should be computationally infeasible to find a different message `m2` such that:

H(m1) = H(m2)

### Collision Resistance

It should be computationally infeasible to find any two different messages such that:

H(m1) = H(m2)

Because of the birthday bound, generic collision search against a 256-bit hash requires approximately:

2^128 operations.

---

## 3. Avalanche Effect

A small change in the input should cause a large and unpredictable change in the output.

For example:

"Hello"

and:

"hello"

produce completely different SHA-256 digests even though only one letter changed.

This property helps prevent relationships between similar input messages from being easily visible in their hashes.

---

## 4. SHA-256 Message Padding

SHA-256 processes messages in blocks of 512 bits, or 64 bytes.

Before processing, the message must be padded.

The padding procedure is:

1. Determine the original message length in bits.
2. Append a single `1` bit.
3. Append enough `0` bits so that the message length becomes 448 modulo 512.
4. Append the original message length as a 64-bit big-endian integer.

For example, the message:

"abc"

contains 3 bytes:

3 × 8 = 24 bits

After padding, it occupies one complete 512-bit block.

---

## 5. 32-Bit Words

Each 512-bit block is divided into sixteen 32-bit words:

W0, W1, ..., W15

Since:

32 bits = 4 bytes

sixteen words occupy:

16 × 32 = 512 bits.

SHA-256 then expands these sixteen words into a 64-word message schedule.

---

## 6. Message Schedule

The first sixteen words come directly from the padded message block.

The remaining words are calculated using:

W_t = W_(t-16) + σ0(W_(t-15)) + W_(t-7) + σ1(W_(t-2)) mod 2^32

where:

σ0(x) = ROTR^7(x) XOR ROTR^18(x) XOR SHR^3(x)

and:

σ1(x) = ROTR^17(x) XOR ROTR^19(x) XOR SHR^10(x)

The final schedule contains 64 words:

W0, W1, ..., W63.

---

## 7. Bit Operations

SHA-256 relies heavily on bitwise operations.

### Right Rotation

ROTR rotates bits to the right while moving bits that leave the right side back to the left side.

### Right Shift

SHR shifts bits to the right, discards bits that leave the right side, and inserts zeros on the left.

### XOR

XOR returns 1 when two compared bits are different and 0 when they are the same.

---

## 8. Choice Function

SHA-256 uses the Choice function:

Ch(x,y,z) = (x AND y) XOR ((NOT x) AND z)

Conceptually, each bit of `x` determines whether the corresponding bit should come from `y` or `z`.

---

## 9. Majority Function

The Majority function is:

Maj(x,y,z) = (x AND y) XOR (x AND z) XOR (y AND z)

For each bit position, it returns the value held by the majority of the three inputs.

---

## 10. Big Sigma Functions

SHA-256 also defines:

Σ0(x) = ROTR^2(x) XOR ROTR^13(x) XOR ROTR^22(x)

and:

Σ1(x) = ROTR^6(x) XOR ROTR^11(x) XOR ROTR^25(x)

These functions are used during the compression rounds.

---

## 11. Compression Function

SHA-256 maintains eight 32-bit working variables:

a, b, c, d, e, f, g, h

Each 512-bit message block goes through 64 compression rounds.

During each round:

T1 = h + Σ1(e) + Ch(e,f,g) + K_t + W_t mod 2^32

T2 = Σ0(a) + Maj(a,b,c) mod 2^32

The working variables are then updated:

h = g  
g = f  
f = e  
e = d + T1  
d = c  
c = b  
b = a  
a = T1 + T2

All relevant additions are performed modulo 2^32.

---

## 12. Initial Hash Values

SHA-256 begins with eight standardized 32-bit initial hash values.

These values initialize the internal state before processing the first message block.

After each block is compressed, its result is incorporated into the current hash state.

This allows SHA-256 to process messages containing multiple 512-bit blocks.

---

## 13. Final Digest

After all message blocks have been processed, the eight final 32-bit hash values are concatenated.

8 × 32 = 256 bits

The result is the final SHA-256 digest.

For example:

SHA-256("abc")

produces:

ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad

---

## 14. Relationship to Digital Signatures

Hash functions are an important part of digital signature systems.

Instead of signing an entire large document directly, a cryptographic hash can first produce a fixed-size digest of the document.

The signature algorithm then operates on an appropriate representation of that digest according to the signature scheme.

This provides an important connection between this SHA-256 implementation and the RSA and ECDSA concepts implemented earlier in this repository.

---

## 15. SHA-256 and Post-Quantum Cryptography

Hash functions remain important in post-quantum cryptography.

Quantum algorithms affect hash functions differently from public-key systems such as RSA and ECC.

Grover's algorithm provides a generic quadratic speedup for brute-force search. Therefore, a rough generic estimate reduces the preimage security of SHA-256 from 2^256 classical work to approximately 2^128 quantum search operations.

This is one reason sufficiently large hash outputs remain useful in post-quantum cryptographic designs.

## 16. Implementation

This project implements SHA-256 from scratch in Python for educational purposes.

The implementation includes:

- 32-bit rotations and shifts
- Choice and Majority functions
- Small sigma functions
- Big Sigma functions
- SHA-256 message padding
- 512-bit block processing
- 64-word message schedule expansion
- 64 compression rounds
- SHA-256 initial hash values
- SHA-256 round constants
- Multi-block message processing
- 256-bit hexadecimal digest generation

The implementation is validated against known SHA-256 test vectors, including:

- Empty message
- `"abc"`
- `"hello"`
- A multi-block 100-byte message

The complete repository test suite passes 140 tests.

## 17. Educational Limitations

This implementation was created to understand the internal mathematical and algorithmic structure of SHA-256.

It should not replace established cryptographic libraries in production systems.

Production cryptographic software requires careful attention to implementation security, testing, performance, interoperability, and other engineering considerations.

The purpose of this implementation is educational and research preparation, particularly as a foundation for studying modern and post-quantum cryptography.
